## 1. 目的とスコープ

### 1.1 目的
ライブポーカートーナメントの運営者が、ブラインドストラクチャーの作成から
当日の進行・表示までを1つの Web システムで行えるクロックを提供する。

### 1.2 v1 に含むもの
- トーナメント／ストラクチャーの作成・編集（表計算型エディタ）
- ストラクチャーの「おまかせ」自動生成（リンク哲学ベース、§9）
- トーナメント進行管理（開始／一時停止／レベル操作／人数カウント）
- TV 向けクロック表示（ブラウザ、分割表示 1／2／4）
- 複数端末へのリアルタイム同期（サーバー権威＋SSE）
- ミックスゲーム対応: レベルごとにゲーム種別を持ち、強制ベット表示を
  ゲーム形式に応じて切り替える（§7.7）。スタッド系ラウンドの有無は
  管理画面で設定する（§4.3）

### 1.3 v1 に含まないもの（SunVy から切り離す範囲）
- 会員管理・QR 受付、ポイント／ランキング集計
- イベント集客配信（Poker Fans 的な告知機能）
- 座席表管理（シート移動・着席管理）。人数カウントのみ扱う
- Payout Matrix の高度な編集（プライズは手入力表示＋単純な自動計算のみ、§10）
- ネイティブアプリ（Fire TV Hosted Web App 化、PWA インストール対応は将来の包み直し）

### 1.4 用語
- **管理 Web**: 運営者向け画面群。ログイン必須
- **表示画面（Display）**: TV 等に出す読み取り専用クロック。表示トークンでアクセス
- **ストラクチャー**: レベル列の定義。レベル行と Break 行からなる
- **マスター梯子（Master Ladder）**: 許容ブラインド値だけからなる正規の数列（§9.2）

## 3. 全体構成

```
[管理 Web (PC/スマホ)] --REST(コマンド/CRUD)--> [サーバー] <-- DB
[表示画面 (TVブラウザ)] --SSE(イベント購読)--> [サーバー]
[表示画面]             --REST(スナップショット, 30秒保険)--> [サーバー]
```

- サーバーが唯一の正本（Single Source of Truth）。端末は状態を持たない
- サーバー実装言語・FW は本仕様では固定しない（単一バイナリ配布が望ましい）
- 同時接続規模の想定: 1トーナメントあたり表示 1〜8 台、管理 1〜3 台。
  全体で同時数百接続程度までを v1 の設計範囲とする

## 4. 画面構成

### 4.1 管理 Web
1. トーナメント一覧／作成
2. ストラクチャー・エディタ（§8）※中核画面
3. おまかせ生成ウィザード（§9.5）
4. 進行コントロール（§6）: 開始／Pause／再開、前後レベル、時間±調整、
   人数カウント操作（エントリー、バスト、リバイ、アドオン、リエントリー）
5. 外観設定（§7.6）: ロゴ、背景、色、レイアウト、プライズ表示、下部コメント
6. 表示デバイス管理: 表示 URL／トークンの発行、分割レイアウトの割当

### 4.2 表示画面
- URL: `/display?token=<表示トークン>`（トークンで対象トーナメント／レイアウトを引く）
- 読み取り専用。操作 UI は出さない（設定は隠し操作のみ: 長押し等）
- 16:9 前提、遠距離視認性を最優先した特大タイポグラフィ

### 4.3 トーナメント設定：ゲームミックス（D10）
トーナメント作成／設定画面で以下を決める:
- **ゲーム構成**: 単一ゲームかミックスか。ミックスの場合は
  ローテーションするゲーム種別の並びを編集できる
  （例: HORSE 相当、8-Game 相当の並びをプリセット＋カスタムで指定）
- **スタッドラウンドの有無**: ON/OFF トグル。OFF の場合は
  スタッド系ゲームがローテーション候補から外れ、エディタの
  スタッド用列（ANTE／BRING-IN／COMPLETE）も表示されない
- **ローテーション単位**: クロックはハンド数を数えられないため、
  v1 では「1 ゲームあたりのレベル数」（既定 1）で切り替える。
  オービット／ハンド数ベースの切替は手動のゲーム変更操作で代替する
- ゲーム種別の例: NLHE、PLO、Limit Hold'em、Omaha Hi-Lo (Limit)、
  Seven Card Stud、Stud Hi-Lo、Razz、2-7 Triple Draw 等。
  種別の追加はデータ定義の追加で済む構造にする

## 5. 同期仕様（D1）

### 5.1 時刻モデル
- サーバーはタイマー状態を以下で保持する:
  - `status`: `waiting | running | paused | break | finished`
  - `current_index`: 現在のストラクチャー行インデックス
  - `level_ends_at`: 現在行の終了時刻（サーバー時刻、epoch ms）。`running` 時のみ有効
  - `paused_remaining_ms`: `paused` 時に保持する残り時間
  - `structure_version`: 構造の版（§8.5）
  - `seq`: イベント通し番号（単調増加）
- 表示端末の残り時間 = `level_ends_at - (端末時刻 + オフセット)` を
  100〜250ms 間隔でローカル計算して描画する
- オフセット補正: 接続時および再接続時にサーバー時刻を取得し、端末時計との差を保持する

### 5.2 配信（SSE＋REST）
- 購読: `GET /api/tournaments/{id}/events`（SSE）
  - イベント形式は transport 非依存に固定する:
    `{seq, type, tournament_id, structure_version, server_time, payload}`
  - イベント種別: `started / paused / resumed / level_changed / time_adjusted /
    structure_updated / counts_updated / appearance_updated / finished`
  - ハートビート: 15〜30 秒間隔のコメント行で半開き接続を検出する
  - 再接続は EventSource の自動再接続＋`Last-Event-ID` に任せ、
    復帰直後に必ずスナップショットを再取得して整合させる
- コマンドと取得は REST:
  - `GET /api/tournaments/{id}/snapshot` : 全状態の一括取得（初期表示と復帰用）
  - `POST /api/tournaments/{id}/commands` : `{type: pause|resume|next|prev|adjust_time|...}`
- 保険: 表示端末は 30 秒に 1 回スナップショットをポーリングし、
  イベント取りこぼしを検出・修正する（`seq`／`structure_version` の不一致で判定）
- WebSocket は v1 では採用しない。表示側からの双方向・高頻度通信が必要に
  なった場合に、イベント形式を変えずに transport のみ差し替える

### 5.3 レベル遷移
- レベル遷移はサーバー権威で行う。`level_ends_at` 経過をサーバーが検出し、
  次行へ進めて `level_changed` を配信する
- 表示端末は自律で次レベルへ進まない（端末ごとの遷移割れを防ぐ）。
  ただし接続断の間は既知の構造から予測表示を続け、オフライン表示を出す

### 5.4 接続断時の挙動
- SSE 切断中もローカル刻みを継続し、画面隅にオフライン表示を出す
- 復帰時はスナップショットで再同期し、予測表示との差分を吸収する

## 6. 進行コントロール仕様

### 6.1 基本操作
- 開始、Pause、再開、次レベル、前レベル、リセット
- 時間±調整（±10秒、±1分、カスタム）
- 開始前は構造先頭に Break 行を置く運用、または `waiting` 状態で
  「Waiting To Begin」を表示する（SunVy 方式）。Break 行方式の場合は 2 時間以下

### 6.2 人数カウント
- 操作: エントリー追加、バスト（脱落）、リエントリー、リバイ、アドオン
- 自動再計算して表示へ反映する項目:
  - 残り人数／総エントリー数
  - リバイ数、アドオン数、リエントリー数
  - 総チップ量 = (エントリー＋リエントリー)×開始スタック
    ＋ リバイ×リバイスタック ＋ アドオン×アドオンスタック
  - アベレージスタック = 総チップ量 ÷ 残り人数
- 各種カウントの手動補正も可能とする（SunVy 同様）

### 6.3 Pause とオーバーシュート対策（D6）
- ハンドストップ（人手の Pause）のオーバーシュートは人間側が支配的で、
  通常運用で 1.5〜3 秒、構えた状態で 0.5〜1 秒、システム側は 0.2〜0.6 秒程度
- 対策を仕様とする:
  - Pause ボタンは確認ダイアログなし、進行画面で常時最前面・特大とする
  - 残り時間は「表示へ反映された時刻」でなく
    「サーバーが Pause コマンドを受信した時刻」で確定する
  - Pause 直後に「−5秒／−10秒」のワンタップ補正ボタンを提示する

## 7. クロック表示仕様

### 7.1 レイアウト（SunVy 準拠）
- 上部: トーナメント名＋日付、ロゴ
- 中央特大: 残り時間（MM:SS、1時間超は H:MM:SS）、現在レベル番号
- 強制ベット: 現在レベルのゲーム形式に応じた表示（§7.7）。
  次レベルの強制ベットも同じ形式で予告する
- ゲーム名: ミックスの場合は現在のゲーム種別を大きく表示し、
  次のゲームも予告する。単一ゲームの場合は省略可
- 統計: 残り人数／総エントリー、リバイ数、アドオン数、アベレージスタック
- フッター: 次の Break までの時間、レイトレジスト締切
  （締切レベルと残り時間）、下部コメント欄
- Break 中は全面 Break 表示（残り時間特大＋次のレベル予告）

### 7.2 下部コメント
- 短文はそのまま表示、長文は横スクロール
- 改行で次文へ切り替える複数行登録が可能
- 色変更可。非表示設定可

### 7.3 音声
- レベルアップ時・Break 開始時の効果音／アナウンス（ON/OFF、音量）
- 残り 1 分等の警告音は設定可能とする

### 7.4 分割表示（D2）
- レイアウト: 1（全画面）／2（横並び）／4（2×2）
- 各スロットは独立にトーナメントを購読し、統計・Next Break・
  レイト締切をスロットごとに計算する
- 音声を出すスロットは指定した 1 つだけを既定とし、他はミュート
  （同時レベルアップ時の合唱防止）。スロットごとに変更可
- レイアウト切替は表示端末側でも管理 Web からでも行える

### 7.5 ブラウザ前提の要件（D5）
- フルスクリーン化は初回タップ起点（ブラウザ制約）
- Wake Lock API が使える環境では画面消灯を抑止する。
  使えない環境（Silk 等）では OS 側スクリーンセーバー設定任せとし、
  その旨をセットアップガイドに明記する
- リロード／再起動してもスナップショット取得で即復帰する（端末に状態を持たない）
- 対応ブラウザ:  PC／タブレットのモダンブラウザ、Fire TV Stick の Silk

### 7.6 外観設定
- ロゴ画像、背景画像、配色、プライズ表示の有無、タイトル表示形式
- 店舗デフォルト設定とトーナメント個別設定を持ち、個別が優先する
  （互いに上書きしない、SunVy 方式）

### 7.7 強制ベット表示：ミックス対応（D9）
表示する強制ベットの組は、現在レベルのゲーム形式で決まる:

- **ブラインド系（NL／PL）**: SB ／ BB ／ ANTE
  （ANTE は BB アンティ。無い形式では項目ごと省略）
- **ブラインド系（Limit）**: SB ／ BB ／ BIG BET ／ ANTE
  （BIG BET は後半ストリートのベット額、通常 BB の 2 倍。
  ANTE は無いゲームでは省略）
- **スタッド系（Limit Stud／Razz／Stud Hi-Lo）**: BRING-IN ／ COMPLETE ／ ANTE
  （ブラインドは存在しない。BIG BET は COMPLETE の 2 倍として
  導出できるため v1 では表示項目に含めず、必要なら設定で追加表示可とする）

実装上の扱い:
- レベル行は「ゲーム種別＋形式（blind-nl / blind-limit / stud-limit）」を持ち、
  強制ベットは形式ごとのフィールド集合で保持する（§11）
- 表示画面は形式に応じてラベルと項目を切り替える。項目の欠けた
  レベルでは詰めて表示し、空ラベルを残さない
- ゲームが切り替わるレベルでは、レベルアップ表示と同時に
  ゲーム名と強制ベット形式の切替を明示する（音声アナウンスも対象）

## 8. ストラクチャー・エディタ仕様（中核）

### 8.1 基本形
- 1 行 = 1 レベル（または Break 行）のスプレッドシート形式
- セルのインライン編集、タブ／Enter でのセル移動
- 列: `# / 種別 / ゲーム / 強制ベット（形式で可変、§7.7）/ 時間(分) / 累計時刻 / マーカー`
  - ブラインド系の行: SB／BB／BIG BET（Limit のみ）／Ante
  - スタッド系の行: Ante／Bring-in／Complete
  - スタッド無効（§4.3）のトーナメントではスタッド系の列・候補を出さない
  - ミックスではローテーション（§4.3）からゲーム列を自動で割り当て、
    個別行での手動変更も可能とする
- マーカー: レイトレジスト締切、リバイ終了、カラーアップ、アドオン Break 等
- 行操作: 挿入、削除、複製、ドラッグ並べ替え、複数行選択の一括変更
  （時間一括設定、区間の間引き等）
- Undo/Redo、下書き自動保存

### 8.2 入力支援
- 次レベル候補提示: 現在の BB に対する倍率ボタン（×1.25／×1.5／×2）と、
  マスター梯子上の次の綺麗な値を候補として提示する
- テンプレート: 構造の保存・複製・呼び出し
- ネスト: 既存構造の全部または区間を現在の構造へ差し込む（SunVy のネスト相当）
- 貼り付け取り込み: スプレッドシートからの表コピペで一括生成、CSV 入出力

### 8.3 Break 支援
- 「N レベルごとに M 分」を一括挿入／除去
- カラーアップ候補位置（§9.3）では Break 挿入を提案する

### 8.4 検証とシミュレーション（リアルタイム）
検証（警告表示、保存は妨げないものと妨げるものを分ける）:
- BB の単調増加違反、SB ≥ BB（意図的な SB=BB は警告のみ）
- 前レベルからの BB 上昇が 2 倍超のジャンプ
- 最小チップ単位で割り切れないブラインド値
- 「綺麗でない数」の警告: 7 の倍数系など両替負荷の高い値
  （例: 700/1400 は 1000/1500 への変更を提案する、§9.3）。
  可否は値単体でなく SB/BB の組で判定する（付録 B7:
  800/1600 は可、800/1500 は警告）
- Ante > BB、時間 ≤ 0（これは保存不可）

シミュレーション（常時表示）:
- 総所要時間、開始時刻入力による終了予定時刻
- レイトレジスト締切のレベルと時刻
- 圧迫度グラフ: 想定エントリー数と開始スタックから、
  各レベルでのアベレージスタック（BB 換算）の推移を表示する
- 終了予測: R13（ヘッズアップでアベレージ 10BB）に基づき、
  終了想定レベルとその到達時刻をグラフ上にマーカー表示する

### 8.5 開催中の編集（D4）
- 進行中・終了した行はロック（グレー表示）し、編集可能境界を明示する
- 編集は次レベルから反映する。現レベルの SB/BB/Ante/時間は変更不可
  （時間変更は §6.1 の時間±調整で行う）
- 変更のたびに `structure_version` を +1 し、`structure_updated` を配信する
- 変更履歴（誰が・いつ・何を）を残し、差分を表示できる

## 9. おまかせ生成仕様（リンク哲学ベース）

### 9.1 設計原則
- 生成は「叩き台」を作ること。生成結果は §8 のエディタに流れ、
  そのまま手直しできることを前提とする
- 数式による補間生成はしない（§9.2）。検証ルール（§8.4）と
  生成ルールは同じ制約セットを共有する

### 9.2 マスター梯子
- 許容ブラインド値のみからなる正規数列を定義する。
  付録 A の転記で全域が確定済み:
  BB の仮数部は {1, 1.2, 1.5, 2, 2.5, 3, 4, 5, 6, 8} × 10^n
  （最小桁は 100, 200, 300, 400, 500, 600, 800, 1000… と続く）
- SB は原則 BB の 1/2 だが、基本形の実例は厳密な半分ではなく
  「割り切れる綺麗な値」へ寄せている（付録 A の読み取り参照）。
  検証ルール（§8.4）でも SB の厳密な半分は要求しない
- Ante は原則 BB と同額（BB アンティ）。序盤のアンティカット
  （初期ポットを抑えるための減額）をオプションとする
- 生成はマスター梯子からの「間引き」と「繰り返し」でのみ行う。
  梯子に無い値（例: 1400, 1800, 2400）を生成してはならない

### 9.3 ルールセット（記事からの形式化）
- R1 上昇率: 3 レベルで BB が 2 倍を基本とする
- R2 開始深度: 標準は 200〜300bb。スタックが 100bb になるレベルが
  L2〜L5 に入るよう開始点（開始 BB／スタック）を調整する
- R3 Duration: 全レベル均一が基本。終了目標時刻と想定人数から逆算する
- R4 Duration 下限: 原則 15 分未満にしない（1 レベルでボタンが一周する根拠）。
  速くする必要がある場合は Duration を割る前に間引き率を上げる
- R5 間引きの作法: 上昇額の単調性が壊れる抜き方はしない
  （例: 200→300→500→600 となる抜き方は禁止）。
  抜き方には全体間引き／後半ターボ等のコンセプトを一貫させる
- R6 頭抜き: 開始深度は Turbo 100bb、Hyper Turbo 75〜50bb を目安に
  序盤レベルを削って調整できる
- R7 Slow 化の作法: 途中に新規レベルを差し込まない。
  同一レベルの繰り返し、または Duration 増加で対応する
- R8 綺麗な数: 両替負荷の高い値を避ける。特に 700/1400 型は禁止し、
  代替（1000/1500 型）を用いる。SB が両替を強いる値になる組み合わせも避ける
- R9 Break: 約 2 時間ごとに 10〜20 分。カラーアップを伴う Break は 10 分以上
- R10 カラーアップ: BB が次のデノミの 3〜5 倍（理想 4 倍）になる
  タイミングで行い、直近の Break と一致させる
- R11 レイトレジスト: 開始スタックが 15〜30bb になるレベルで締め切る。
  いかなる場合も 12.5bb 未満でのエントリーを許す締切にしない
- R12 形状プロファイル:
  - カジノ型: 全区間一定の上昇率（R1 を素直に適用）
  - アミューズ型: レイトレジスト手前を Slow（密／繰り返しあり）にし、
    締切後は間引き率を上げて後半 Turbo にする
  - バブル配慮型（任意）: 想定 ITM 圏付近のレベルをやや Slow にする
- R13 終了条件（見積もりモデル、既定）: トーナメントの終了は
  「ヘッズアップ（残り 2 名）時点でアベレージスタックが 10BB になる頃」
  と定義する。総チップ量を T とすると終了 BB の目安は
  **BB_end = T ÷ 2 ÷ 10 = T / 20**。
  10BB という値はパラメータ（`end_avg_bb_hu`、既定 10）として
  変更可能にするが、既定は変えない

### 9.4 生成手順
1. 入力から総チップ量 T を算出する（想定エントリー × 開始スタック
   ＋想定リバイ／アドオン分）
2. R13 で終了 BB を見積もる: BB_end = T / 20。
   実際の到達点はマスター梯子上で BB_end に最も近い値（対数距離）に
   スナップしたレベルとする
3. R1 を基準に必要レベル数を求め、マスター梯子上で開始点と到達点を決める
4. 目標総時間から Duration を逆算する。15 分を割る場合は
   R4 に従い間引き率を上げてレベル数を減らし、再計算する
5. R2 を満たすよう開始深度を微調整する
6. R11 でレイト締切位置を、R9/R10 で Break とカラーアップ位置を配置する
7. プロファイル（R12）に応じて区間ごとの間引き率を調整する
8. 生成結果をエディタへ出力し、検証（§8.4）を通過した状態で提示する

### 9.5 ウィザード入力項目
- 必須: 想定エントリー数、開始スタック、開始時刻、終了目標時刻、
  タイプ（通常／ターボ／ハイパー／ディープ）、プロファイル（カジノ型／アミューズ型）
- 任意: 最小チップ単位、レイトレジスト希望（時間または締切深度）、
  リバイ／アドオンの有無とスタック量、Break 間隔の希望、
  終了アベレージ深度 `end_avg_bb_hu`（既定 10、R13）

## 12. 非機能要件
- 同期ずれ: 同一トーナメントを表示する端末間の表示差は 1 秒未満を目標とする
- 復旧: 表示端末・管理端末の再起動、サーバーの再起動後も
  トーナメント状態が復元されること（状態は DB に永続化）
- 長時間運用: 10 時間超の連続運転で接続が維持されること
  （SSE ハートビートと自動再接続で担保）
- 操作応答: Pause 等のコマンドは受信時刻ベースで確定し、
  表示反映は 1 秒以内を目標とする（人間側オーバーシュートが支配的、§6.3）

  現行の基本形（B1）は 1500 を採る。おまかせ生成の既定は B1 系とし、
  1600 系はテンプレートとして選択可能に留める
